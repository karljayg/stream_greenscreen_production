# ?? Dynamic Music System for SC2 Broadcast (Full Specification)

---

## ?? Goal

Create a real-time adaptive music system for StarCraft II broadcasts that dynamically selects and transitions music based on:

* Game state (via SC2 Client API)
* Production actions (observer / director inputs)
* Twitch chat signals (mood, hype, warnings)

The system should feel like a **cinematic film score** that evolves naturally with each match.

---

# ?? Core Principles

1. **Game-driven, not chat-driven**

   * Game state defines structure
   * Chat modifies intensity and early warnings

2. **Cinematic flow over reactivity**

   * Avoid rapid switching
   * Prioritize smooth transitions and narrative arc

3. **Production overrides everything**

   * Manual/production triggers take priority over all signals

4. **Consistency of style**

   * All music follows epic cinematic orchestral style

---

# ??? System Architecture

## Components

### 1. SC2 Client (Local)

* Endpoint: http://localhost:6119/game
* Provides:

  * game time
  * players
  * game state (in-game, replay, score screen)

---

### 2. Local Bridge (Helper App)

Runs on observer PC

Responsibilities:

* Poll SC2 API (every 250–500ms)
* Normalize data
* Send updates to backend (PHP API)

Endpoints:

* `/game`
* `/ui` (optional)

---

### 3. Twitch Chat Reader

* Parses messages in real-time
* Extracts:

  * hype level
  * fear/suspense
  * rush/cheese detection
  * message velocity

---

### 4. Production Web App (PHP)

Main orchestration layer

Responsibilities:

* Receives:

  * SC2 data
  * chat signals
  * production actions
* Maintains current **music state**
* Outputs:

  * target music state
  * transition type
  * intensity level

---

### 5. Music Engine (Local Playback)

Runs on production machine

Responsibilities:

* Plays music tracks
* Handles transitions (crossfade, stingers)
* Maintains playback state

# ?? Game Phase Model

## Time-Based Structure

### 0:00–2:00 ? Opening

* Default: opening
* Chat alert ? suspense

---

### 2:00–5:00 ? Build-Up Phase

* Default: combat_mid
* Small skirmishes possible
* Chat alert (rush/cheese) ? combat_high early
* Calm chat ? remain combat_mid

---

### ~5:00 ? First Major Fight (Critical Anchor)

* Force escalation ? combat_high
* Chat hype spike ? combat_extreme

---

### 5:00–10:00 ? Core Mid Game

* Alternate between:

  * combat_mid
  * combat_high
* Chat modifies intensity (NOT state spam)

---

### >10:00 ? Late Game

* Bias toward:

  * combat_high
  * combat_extreme
* Larger fights, higher stakes

---

### Endgame

* Trigger:

  * production GG
  * base destruction
  * chat “GG” spam

Flow:

```text
combat_extreme ? climax ? victory/defeat
```
